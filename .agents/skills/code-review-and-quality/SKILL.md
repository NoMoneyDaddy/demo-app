# code-review-and-quality

每次合併前都過五道門。

## 檢查面向

1. 正確性
2. 可讀性
3. 架構邊界
4. 安全性
5. 效能

## 規則

- 找 bug 與風險優先
- 有行為改動卻沒驗證，要擋下
- 自動格式化 / safe fix 不取代 review 本身
